**ConversationHandler** в библиотеке `python-telegram-bot` (PTB) — это специализированный мета-хендлер, реализующий паттерн **конечного автомата** (Finite State Machine, FSM).

Он предназначен для управления многошаговыми диалогами (опросы, онбординг, оформление заказов), связывая отдельные сообщения пользователя в единый последовательный сценарий.

---

### Главные компоненты

Класс `ConversationHandler` состоит из трёх ключевых блоков:

* **`entry_points` (Точки входа):**
Список базовых хендлеров (обычно `CommandHandler("start", ...)`), которые запускают диалог, когда пользователь находится вне сценария.
* **`states` (Таблица переходов):**
Словарь вида `{состояние: [список хендлеров]}`, описывающий, какие функции должны реагировать на входящие сообщения на конкретном шаге.
* **`fallbacks` (Аварийный выход):**
Обработчики, доступные из любого шага диалога (например, команда `/cancel` или кнопка «Назад»), прерывающие сценарий.

---

### Механика работы под капотом

Внутри экземпляра `ConversationHandler` хранится внутренняя таблица состояний (по умолчанию в оперативной памяти): **`В БУДУЩЕМ В REDIS например`**

```python
conversations = {
    (chat_id, user_id): current_state
}

```

Жизненный цикл обработки запроса строится следующим образом:

1. **Вход в диалог:**
Пользователь присылает команду из `entry_points`. Запускается стартовая функция. Она завершается оператором `return STATE_NAME`, где `STATE_NAME` — целочисленный идентификатор или строка следующего шага. PTB сохраняет этот идентификатор в таблицу для текущего `(chat_id, user_id)`.
2. **Маршрутизация шагов:**
Когда приходит очередное сообщение, `ConversationHandler` проверяет таблицу:
* Если пары `(chat_id, user_id)` нет — сообщение игнорируется (или проверяется на соответствие `entry_points`).
* Если пользователь находится в статусе, скажем, `1`, PTB опрашивает только те хендлеры, которые указаны в `states[1]`.


3. **Обновление состояния:**
Вызванный хендлер валидирует ввод, сохраняет данные во временный словарь `context.user_data` и возвращает следующий статус (`return NEXT_STATE`). Таблица внутри PTB мгновенно обновляется.
4. **Завершение или сброс:**
Когда диалог закончен (или вызвана отмена из `fallbacks`), функция возвращает системную константу:
```python
return ConversationHandler.END  # целочисленная константа -1

```


PTB удаляет ключ `(chat_id, user_id)` из внутренней мапы, возвращая пользователя в базовый режим работы бота.

---

### Архитектурные преимущества

* **Изоляция контекста:** Сообщения обрабатываются строго в контексте текущего вопроса, исключая ложные срабатывания общих хендлеров бота.
* **Встроенный контекст сессии:** Метод передает объект `context`, где `context.user_data` выступает промежуточным буфером для сбора данных со всех шагов перед единой записью в базу данных.
* **Поддержка постоянства (Persistence):** При перезапуске процесса таблицу состояний и `user_data` можно сохранять на диск, в базу данных или в Redis через абстракцию `BasePersistence`.
